Recovery and document actions

Current behaviour for the approved repair plan. These changes use the existing file pickers, confirmation dialog, status text and export toast. They add no new navigation surface.

Malformed or unsupported archives fail before replacement. A database backup failure cancels restore. Cancel preserves the current workspace. Restore failure rolls the transaction back. Success clears the old editors, reloads the document lists, and reports the safety-copy location in the status text.

Applications and letters

Newly sent applications capture document content. Open resume opens that content as a separate editable copy. Existing historical links without a captured version are described as live links in status text.

Application save failures remain pending and appear in the existing Applications summary. Done waits for pending changes to save. Workspace restore waits until folder sync has finished. File Save retries. If persistence fails on window close, the existing Save, Discard and Cancel dialog allows an explicit decision.

Draft with AI uses the letter's own source and job description. An existing body requires the current confirmation pattern before replacement. Each letter has its own undo history; changing the resume behind it does not change its drafting source.
