Tailor to Job panel

Currently at Tools ▸ Tailor to Job ▸ …. It does two separable things: ATS keyword analysis, which is pure local computation and always works, and AI rewrites, which need a model. The panel shows the analysis unconditionally and treats rewrites as an optional layer on top — the "degrade, not gate" rule applied to the feature that most needs it.

Rules

The match score renders with no model configured. KeywordAnalyzer is local computation — score, matched terms, missing terms and warnings all work offline. Only the "Suggested rewrites" section depends on a model, and it is the only part that disappears without one.

Every rewrite is shown as a before/after diff on a named target. The header states exactly which achievement it will replace ("Northwind Systems · achievement 1") because JobTailoringService addresses achievements by index through AchievementLines. Showing the target makes an off-by-one visible to the user instead of silently rewriting the wrong bullet.

Nothing applies until Apply. Accept/Reject stage a decision; the footer count ("Apply 1 change") tells the user how many edits are pending. Rewrites are irreversible-feeling even though undo exists, and a per-suggestion accept that instantly mutated the résumé would make the preview thrash.

Missing keywords are advisory, never auto-inserted. Stuffing a résumé with terms the person cannot back up is how people fail interviews. The chips report; the human decides.
