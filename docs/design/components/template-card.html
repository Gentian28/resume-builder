The thumbnail stays white in both themes — deliberately

A résumé is printed on white paper. Tinting the thumbnail to match a dark UI would misrepresent the output, and the user is choosing a document, not a UI skin. The card chrome changes with the theme; the page inside never does.

Same reason the selected-state tick flips colour: on dark the indigo fill is light, so the glyph must be near-black (on-accent: #0F1115). See the colour card for why this is arithmetic rather than preference.

Where the thumbnails come from — no new rendering code

ResumeBuilder.Export/PngExporter.cs already renders any template to PNG. Render each against samples/sample-resume.json and cache to %LocalAppData%/ResumeBuilder/thumbnails/<templateId>.png, keyed on template id + app version.

Generate lazily on first gallery open, not at startup or build time — 25 renders at once would stall the UI thread, and TemplateRegistry changes between releases so build-time assets would go stale.

Aspect ratio fixed at 210:297 (A4), never cropped or letterboxed. A template's whole value proposition is how it uses the page; a cropped thumbnail lies about it.

Render with the template's own default accent, not the user's current Resume.AccentColor — the card advertises the template, it does not preview the user's document.
