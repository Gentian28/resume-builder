Layout rules

Only the section list is fixed width (168 px). Editor and preview are minmax(0,1fr) and minmax(0,1.15fr) — the preview gets slightly more because a page has a fixed aspect ratio and benefits more from width. Extra window width is divided between them instead of pooling as grey.

The preview page caps at a readable size rather than growing forever. Past a point a bigger page stops helping; the surplus becomes symmetric margin, which reads as deliberate framing rather than the current lopsided void.

The section list is navigation, not a reorder widget. It replaces scrolling a single long column and gives each section a home. Reordering moves into "Section order" under Document — a different task that does not belong in the primary navigation.

Item counts sit in the nav (Experience 3, Skills 3). Cheap to compute, and it tells the user where the content is without opening each section.

Every field has a visible label, including filled ones — the placeholder-as-label problem from the baseline. The two-column grid works because labels are above inputs rather than beside them, so nothing depends on a fixed label column.

Still open: the editor is a two-column grid here, which suits short fields but may be wrong for Experience entries with multi-line achievement lists. Those may want a single wide column. Worth resolving when the Experience section gets its own spec card.
